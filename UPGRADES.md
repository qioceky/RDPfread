# RDPfread v1.0 — Daftar Peningkatan

Perapihan total dari versi awal RDPfread (satu file workflow, dibuat 2026-10-10) menjadi project modular setara QVPS:

## Struktur & workflow
1. **Modular** — dari 1 file `main.yml` menjadi workflow `rdp.yml` + 14 script PowerShell di `scripts/` + `config/`, masing-masing satu tugas dan bisa diuji terpisah.
2. **Input workflow lengkap** — durasi, hostname, username, pilihan runner (windows-2022/2025/latest), preset, timezone, dan auto-renew bisa dipilih saat Run, bukan edit file.
3. **Validate CI** — `validate.yml` memeriksa YAML (Ubuntu) dan sintaks semua `.ps1` dengan parser PowerShell + PSScriptAnalyzer (Windows).
4. **Actions v5 & concurrency** — `actions/checkout@v5`, `upload-artifact@v5`, dan concurrency group agar hanya 1 sesi aktif dalam satu waktu.
5. **Cleanup otomatis** — run lama dihapus, disisakan 10 terakhir.

## Keamanan
6. **Tanpa password hardcoded** — password user RDP 100% dari secret `RDP_PASSWORD` (min. 8 karakter, divalidasi di awal sesi).
7. **Tanpa unduhan script eksternal acak** — satu-satunya unduhan adalah installer resmi Tailscale dari `pkgs.tailscale.com`; software preset dari winget/Chocolatey bawaan image.
8. **RDP khusus tailnet** — rule firewall bawaan yang terbuka untuk semua alamat dimatikan, diganti rule khusus `100.64.0.0/10`; NLA tetap wajib.
9. **Rekomendasi repo Private** — ditegaskan di README, PANDUAN, dan kedua wizard karena state disimpan di Release repo.

## Fitur baru (menyusul QVPS)
10. **State persisten** — `C:\RDPData` + Desktop & Documents user, checkpoint 15 menit, manifest pemetaan path, enkripsi AES-256 opsional.
11. **Dashboard status** — branch `status` dengan `rdp-status.json` (schema v2) + `STATUS.md`.
12. **Notifikasi** — Telegram / Discord / webhook untuk event ready, expiring, handover, stopped.
13. **Preset software** — minimal / web / dev / full via winget (fallback choco), versi tools dicatat ke status.
14. **Heartbeat resource** — CPU/RAM/disk + status Tailscale tiap 5 menit, auto-reconnect Tailscale, auto-restart service RDP.
15. **Auto-renew / handover** — sesi berikutnya di-dispatch 20 menit sebelum habis dengan input yang sama.
16. **Setup wizard ganda** — `setup-wizard.ps1` untuk Windows dan `setup-wizard.sh` untuk Linux/Termux.
17. **Dokumentasi lengkap** — README baru + PANDUAN langkah demi langkah + file ini.

## Fitur khas Windows (pembeda dari QVPS)
18. **Preset `desktop`** — pengalaman desktop penuh: PowerToys, Windows Terminal, PowerShell 7, VLC, LibreOffice, OBS Studio (di samping isi preset `full`).
19. **Tweak Windows otomatis** — power plan High Performance tanpa sleep, Explorer menampilkan ekstensi & file tersembunyi (hive Default User), long paths, redirection clipboard/drive/audio RDP, shortcut folder persisten di desktop.
20. **File koneksi `.rdp` siap klik** — artifact `rdpfread-connection` per run; tanpa password di dalamnya (mstsc/Windows App yang menanyakan).
21. **OpenSSH Server Windows opsional** — input `akses_ssh=ya`: jalur terminal PowerShell ke Windows dari Termux/HP, akun & password sama dengan RDP, firewall tetap khusus tailnet dan rule bawaan yang terbuka dimatikan.

## v1.5.2 (2026-10-25) — hardening hive Default di semua script + guard anti-timpa state
44. **Pelepasan hive Default User terverifikasi di SEMUA script yang menyentuhnya (`setup-games`, `debloat-windows`, `debloat-full`).** Koreksi atas v1.5.1: sesi #25 tetap gagal login meski `default_hive_ok=True`, jadi teori kunci hive setup-windows resmi gugur; tersangka pindah ke edit hive setup-games (nonaktifkan akselerasi mouse) — satu-satunya edit hive di jalur game yang belum dikeraskan v1.5.1 — dan pola unload-sekali-tanpa-verifikasi yang sama masih ada di kedua script debloat. Ketiganya kini memakai pola v1.5.1 (GC penuh + unload dicoba ulang 3x + verifikasi dua lapis: mount hilang DAN NTUSER.DAT tidak terkunci), hasil jujur di status (`games_default_hive_ok`, `debloat.default_hive_ok`, `debloat_full.default_hive_ok`). **Guard anti-timpa di `persist-state`:** upload ke Release dilewati bila tidak ada profil user sungguhan (sesi belum pernah login) DAN arsip baru jauh lebih kecil dari asset Release yang ada (ambang: remote > 10 MB, baru < 1 MB) — persis pola penimpaan state bagus ±105 MB jadi ±1,5 KB yang terbukti berulang lewat checkpoint/finalize sesi #23–#25; fail-open bila ukuran remote tak terbaca, dan fingerprint lama dipertahankan supaya checkpoint berikutnya tetap membandingkan dengan benar. Tes game ditunda atas pilihan user: v1.5.2 hanya dikirim sebagai kode (CI hijau), sesi ringan #26 tidak diganggu.

## v1.5.1 (2026-10-25) — perbaikan ProfSvc: pelepasan hive Default terverifikasi
43. **Pelepasan hive Default User kini diverifikasi (setup-windows.ps1).** Insiden 23–25 Okt: dua sesi game berturut-turut gagal login ("User Profile Service failed the sign-in") padahal debloat sudah dimatikan di sesi kedua — jadi debloat resmi gugur sebagai tersangka dan satu-satunya editor template profil Default yang tersisa adalah tweak Explorer di setup-windows. Penyebab yang diyakini: unload hive sekali + error disembunyikan kadang gagal diam-diam (handle registry belum lepas), sehingga NTUSER.DAT Default tetap terkunci dan Windows gagal menyalin template itu saat membuat profil baru. Perbaikan: unload dicoba ulang 3x dengan jeda + GC penuh (termasuk WaitForPendingFinalizers), lalu diverifikasi dua lapis — mount hive benar-benar hilang DAN file NTUSER.DAT bisa dibuka eksklusif (tidak terkunci) — hasilnya dilaporkan jujur di status `default_hive_ok` (bukan lagi diam-diam sukses). Guard anti-timpa state di persist-state + hardening pola yang sama di script debloat DITUNDA ke rilis berikut; perlindungan state untuk dispatch ini dilakukan prosedural (backup pra-batal + verifikasi ukuran asset).

## v1.4.0 (2026-10-22) — pilihan OS: Windows Server / Linux XFCE4 / Linux SSH polos + target 120 FPS
40. **Sesi Linux (terinspirasi pemilih OS di project sejenis, implementasi khas RDPfread).** Input `runner` kini sekaligus pemilih OS: `windows-2022/2025/latest` (alur Windows seperti biasa) atau `ubuntu-24.04/22.04/latest`, plus input baru `linux_mode`: `desktop` (XFCE4 + XRDP di :3389 + SSH) atau `polos` (SSH saja, tanpa desktop). Minecraft memang sudah `maxFps:120` sejak v1.2.0. Catatan jujur: FPS nyata juga dibatasi aplikasi klien RDP & latensi jaringan; mode Linux/XRDP tidak memakai knob ini.
